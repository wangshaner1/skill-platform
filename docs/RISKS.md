# 企业级风险与合规清单

等级说明：高=会造成安全事故/业务损失；中=影响稳定或信任；低=体验与成本问题。

## 一、数据安全与合规（最高优先级）

| 风险 | 等级 | 场景 | 现有缓解 | 补充建议 |
|------|------|------|----------|----------|
| 企业敏感数据明文入库 | 高 | 任务的 `input_data` 明文存在 SQLite；需求只存哈希但输入数据未脱敏 | 已落地：输入数据 Fernet 加密存储，读取时解密；密钥文件不入库 | 生产建议字段级加密 + KMS 托管密钥；审计只保留数据指纹 |
| 敏感数据外发第三方模型 | 高 | 客户名单、财务、用户隐私随请求发送到云端 LLM | 已落地：手机号/身份证/邮箱/银行卡送模型前自动脱敏；Prompt 注入防护 | 选择合规区域模型或私有化部署；与客户签署数据处理协议 |
| 接口无认证与租户隔离 | 高 | 任何能访问服务的人都能生成/执行/导入，无权限与配额 | 无 | 增加登录/API Key、多租户隔离、操作者审计、调用配额与限流 |
| 输出合规风险 | 中 | AI 可能给出医疗、法律、金融等敏感结论或不当建议 | 无 | 领域白名单、免责声明、人工复核、内容合规过滤 |

## 二、模型与技术风险

| 风险 | 等级 | 场景 | 现有缓解 | 补充建议 |
|------|------|------|----------|----------|
| 幻觉与编造结论 | 高 | LLM 输出格式完美但结论错误，企业据此做经营决策 | 已落地：指标口径库、必填校验、结论-指标一致性检查、提示词要求如实指出负面信号、报告附复核提示 | 高风险结论标注“需人工复核”；关键数字强制从规则引擎出 |
| 模型行为漂移 | 中 | qwen 升级或换模型后，同一 Skill 输出风格/质量变化 | 已落地：Skill 与执行结果记录所用模型名（可追溯）；模型通过环境变量固定 | 发布前跑离线评估集对比新旧模型 |
| 输入超长截断 | 中 | 大文件/长文本超过 max_tokens，分析不完整且不报错 | 无 | 输入大小与 token 预估校验；超限时分段分析或明确拒绝 |
| 单一模型供应商依赖 | 中 | 厂商故障、限流、欠费导致服务不可用 | Redis 缓存部分兜底 | 实现备用模型/多供应商降级（已规划未落地） |
| 流式链路被中间网关掐断 | 中 | 反代/负载均衡空闲超时中断 SSE | SSE 心跳（任务流已加 ping） | 网关层同步配置空闲超时；前端自动重连 |

## 三、业务与运营风险

| 风险 | 等级 | 场景 | 现有缓解 | 补充建议 |
|------|------|------|----------|----------|
| 错误 Skill 上线影响面大 | 高 | 未经验证的 Skill 被大量员工使用 | 已落地：新 Skill 默认草稿状态，发布前需点击“发布”；语义校验 | 生产补人工审核流与灰度发布 |
| 缓存误命中 | 中 | 需求相似但业务上下文不同（如“华东销售”vs“全国销售”） | 已落地：仅精确需求哈希，未启用语义缓存，从设计上规避误命中 | 未来若加语义缓存，必须带人工确认；缓存键加租户/业务域维度 |
| 指标口径不一致 | 中 | 不同 Skill 对“客单价”定义不同，报告打架 | 指标口径库 | 企业级口径字典 + 口径变更通知 |
| 垃圾数据进、垃圾结论出 | 中 | 数据缺字段、异常值、单位不一致 | 已落地：必填 + 类型 + 负值/空列表检查的数据质量门禁，不合格拦截，警告在前端提示 | 增加数值范围/枚举/单位校验与数据质量评分 |
| AI 结论被直接当决策依据 | 高 | 管理层直接把报告当结论，不做复核 | 已落地：执行结果附“AI 生成，关键指标请复核”提示；指标先行 | 输出附置信度与数据来源；建立“AI 结论需人确认”的流程制度 |

## 四、工程运维风险

| 风险 | 等级 | 场景 | 现有缓解 | 补充建议 |
|------|------|------|----------|----------|
| 单机部署无高可用 | 高 | 服务进程崩溃/重启，运行中任务被标记失败 | 重启时标记失败、前端可重试 | 生产改为多实例 + 正式任务队列（Celery/RQ） |
| 任务并发失控 | 中 | 大量并发请求导致线程/内存耗尽 | 无 | 并发上限、排队、超时与取消机制 |
| SQLite 并发写锁 | 中 | 高并发下写入冲突、接口变慢 | 无 | 开启 WAL、或生产换 PostgreSQL |
| Redis 无持久化 | 中 | 重启后缓存全丢，成本反弹 | 内部验证环境可接受 | 生产启用 AOF/RDB、主从与哨兵 |
| 日志/审计无轮转 | 低 | 长期运行磁盘被日志占满 | 无 | 日志轮转、审计归档、敏感字段不落日志 |
| 依赖与版本锁定不完整 | 低 | 传递依赖升级引入不兼容 | requirements 主版本锁定 | 全量锁定（requirements.txt 生成完整清单）、CI 构建 |
| 密钥管理 | 高 | API Key 明文在 .env | .env 不入库 | KMS/密钥服务托管、定期轮换、最小权限 |

## 五、成本与体验风险

| 风险 | 等级 | 场景 | 现有缓解 | 补充建议 |
|------|------|------|----------|----------|
| Token 成本失控 | 中 | 高频调用、大输入重复送模型 | Redis 缓存、指标先行 | 预算上限、按租户配额、token 用量监控与告警 |
| 重复发送大输入数据 | 中 | 同一份数据反复执行 | 执行结果缓存思路 | 数据哈希级结果缓存 |
| 慢响应流失用户 | 低 | 单次生成 30-60 秒 | 流式输出、后台任务 | 模型路由、异步通知、进度反馈 |
| 浏览器本地数据丢失 | 低 | localStorage 被清空后会话与任务记录丢失 | 会话本地存储 | 关键会话同步到后端 |

## 六、治理与人为风险

| 风险 | 等级 | 场景 | 现有缓解 | 补充建议 |
|------|------|------|----------|----------|
| 缺少人工审批链 | 高 | Skill 未经审核直接发布 | 草稿状态字段（未启用流程） | 审核流、发布人/审核人留痕、回滚能力 |
| Skill 所有权不清 | 低 | 员工离职后其创建的经验资产归属不明 | 无 | 企业级资产归属、权限转移流程 |
| 结论迎合倾向 | 中 | 模型生成“看起来正确”的结论，掩盖真实问题 | 已落地：执行提示词要求如实指出负面信号与风险，不得粉饰或迎合 | 评估集包含反例；关键结论要求给出负面证据 |

## 七、落地优先级建议

先补安全与信任底线（P0）：输入数据加密与脱敏、接口认证与租户隔离、错误 Skill 审核上线、AI 结论复核制度。
再补稳定与成本（P1）：任务队列与高可用、并发限制、模型降级、结果缓存、token 监控。
最后做体验与治理（P2）：语义缓存、多租户商业化、资产所有权与审计完善。
