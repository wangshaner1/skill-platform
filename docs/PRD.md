# 产品设计文档（PRD）

## 1. 产品定位

面向企业岗位经验沉淀的 Skill 生成平台。业务人员用自然语言描述岗位经验，平台自动生成结构化、可执行的智能体 Skill，让企业 AI 员工可复用优秀员工的经营分析能力。

## 2. 目标用户

核心用户是**不写代码的业务专家**，包括：

- 电商运营、直播运营、销售管理、用户增长、门店运营等岗位负责人
- 企业内的经营分析、业务数字化团队
- 需要把个人经验复制给 AI 员工的企业管理者

次要用户是**平台管理员/技术运营**，负责审核、治理和发布企业 Skill 资产。

## 3. 解决的核心问题

企业优秀员工的经验通常停留在个人脑中，难以规模化复制；直接使用 ChatGPT 只能获得通用回答，无法沉淀企业私有知识、业务数据口径和标准工作流。

本平台解决：

- 经验难以标准化、复用
- 业务人员不会写代码，无法自行构建 AI 能力
- 通用大模型回答与企业实际业务脱节
- AI 输出质量无法验证、不可治理

## 4. 核心概念：Skill 与 Prompt 的区别

Prompt 只是一段指令，输入给模型后直接得到回答，缺乏结构、契约和可验证性。

Skill 是一份可复用的结构化能力配置，包含：

1. 名称
2. 描述
3. 使用场景
4. 输入数据定义
5. 分析流程
6. Agent Prompt
7. 输出结果模板

Prompt 是 Skill 的组成部分之一；Skill 还包含数据契约、执行流程、输出规范和版本管理。

## 5. Skill 的核心组成

| 组成 | 作用 |
|------|------|
| 名称 | 唯一标识一个岗位能力 |
| 描述 | 说明 Skill 解决什么问题 |
| 使用场景 | 何时应使用该 Skill |
| 输入数据定义 | 明确需要采集哪些字段及类型 |
| 分析流程 | 规定从数据到结论的步骤 |
| Agent Prompt | 约束 AI 员工角色、目标、边界和输出 |
| 输出结果模板 | 保证结果格式稳定、可阅读 |

## 6. 核心业务流程

1. 用户输入自然语言需求
2. 平台调用 LLM 生成 Skill 配置
3. 平台校验配置完整性并展示
4. 用户确认后执行 Skill
5. 系统按分析流程处理输入数据
6. 输出符合模板的分析结果

## 7. MVP 功能范围

- 自然语言输入框
- Skill 自动生成与 Schema 校验
- Skill 配置结构化展示
- 示例业务数据执行
- 分析结果展示
- Skill 资产 JSON 存储与列表读取

## 8. 企业 Skill 资产管理

MVP 阶段用 JSON 文件存储，生产环境演进为数据库 + 对象存储。管理维度包括：

- 版本管理：每次修改生成新版本，保留历史
- 命名空间：按部门、岗位、业务域组织
- 权限控制：谁能创建、审核、使用、发布
- 状态流转：草稿 → 审核 → 已发布 → 下线
- 血缘关系：记录 Skill 引用的数据、模型和版本

## 9. 验证 Skill 是否有效

采用“样例验收 + 在线评估”：

1. 为每个 Skill 配置一组输入样例和预期关键结论
2. 执行后比较关键指标、结论方向和输出格式
3. 建立人工评审：业务专家打分
4. 上线后持续跟踪使用率、采纳率和结果准确率

## 10. 成功指标

- Skill 生成成功率 ≥ 95%
- 单次生成平均耗时 < 60 秒
- 业务人员无需代码即可完成闭环
- 生成结果通过校验和人工复核
